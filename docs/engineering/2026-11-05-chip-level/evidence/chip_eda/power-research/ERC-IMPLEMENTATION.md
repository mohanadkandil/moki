# Generic ERC implementation handoff

`src/blocks/erc.ts` exports the agreed `checkBlockDraft(draft,catalog?)`, `checkPlan(plan,blocks)` and `pinMap(plan,blocks)`. Return gates are `erc` and `power`; each `ok` is derived from that gate's actual error count. All operations are pure and preserve input objects.

29 pure tests passed with `node --import tsx --test tests/blocks-erc.test.ts` (latest 501 ms). Test supplier records are explicitly SYNTHETIC fixtures, never claimed as real LCSC identities. Tests cover complete graph acceptance; malformed/unknown/nonfinite fields; draft self-promotion; catalog/pad mismatches; duplicate/unknown refs and NC wiring; actual decoupling values/net membership/proximity; pull-ups; driver conflicts; separate peak/continuous power, upstream losses and regulator cycles; voltage domains including 5V charger status into3.3V inputs; thermal/dropout; I2C signal/controller/address/pull-up checks; USB-C5.1k CC grounding; strap-state paths and external overrides; charge-only versus system-on-BAT topology; intrinsic charging current; malformed catalog evidence; immutable bases; independent review receipt structure; STM32 string GPIOs, RP2040 numeric GPIOs, reserved pins and sanitized macro collisions.

Draft power-in and ground ports are explicit block-boundary assumptions. Full plans must connect their actual power/ground nets to external sources. `mode:charger` adds programmed charge current to its output demand even without another plan load; source input demand therefore includes charging. Power sink declarations remain additional loads. Input current for linear conversion follows output current; switching input follows worst-case input voltage and declared efficiency. `continuousMa` limits typical sustained demand separately from `maxMa` peak capability. LDO dropout plus thermal/dissipation evidence are required. Drafts validate their claimed continuous rating; plans validate load and rating. Peaks above continuous current produce a transient-verification warning, not a claim of proven burst behavior. Thermal calculations produce an explicit assumption warning.

Static raw plan parameters must equal the materialized block default; otherwise ERC returns `parameter-rebuild-required`. The root library resolves vetted variants/bindings and supplies materialized definitions before invoking this layer. No expression evaluation or arbitrary supplier-value rewriting occurs here.

`pinMap` first requires passing ERC/power gates and exactly one MCU. It emits only actually linked MCU terminals, preserves string or numeric GPIO identities, rejects reserved/ambiguous pads and macro collisions, and aggregates only declared firmware libraries/includes. It does not invent Arduino headers for other families. Macros are `PIN_<REMOTEINST>_<REMOTEPORT>[_SIGNAL]`; pin entries retain `remoteInst.port.signal` addresses.

Catalog evidence is checked when a trusted catalog Map is supplied. Without it, a warning explicitly says catalog identity/pad coverage was not verified. Every pinout must still be marked verified and a content-addressed catalog receipt is required. A draft cannot supply reviewed status or review receipts. A persisted reviewed definition needs a structurally valid independent passing receipt for its exact content hash; authenticating reviewer identities and immutable hashes belongs to the trusted library/promotion layer, not this pure checker.

Limits: keepout/connector-edge physical realization is a later PCB gate and is warned as pending. Discrete battery switch polarity/reverse blocking still require independent circuit review. Current source/dependency facts describe one declared operating source state; alternate battery-only/USB-present states need separately instantiated checks or a richer state contract. Static ERC does not prove transistor behavior, thermal performance, RF, EMI, USB current negotiation, battery protection, component DC-bias derating, copper/routing quality or manufactured fit.

Owner-refocus additions are implemented: explicit schematic sections form a complete unique partition with primary-source page references; inline draft schemas/materialization are checked; cited standard-footprint fallbacks preserve real supplier identity and remain layout-pending. Parallel supply pads on the same IC share their intentional rail/decoupling constraint. Shared-IC thermal and dissipation models sum all simultaneous output/charging losses; separate per-output declarations cannot hide aggregate heating. Direct ground straps are valid without a fictitious resistor, and unused IC power outputs still require source budgets. Latest full TAP evidence: `blocks-erc-test.tap`.
