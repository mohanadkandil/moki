# Fixed-profile native SPICE gate

Public API: `runSpiceChecks(plan, blocks, options?) -> Promise<GateResult>`, exported by `src/blocks/spice.ts`. The optional execution settings isolate artifacts/tests and bound Bun runtime; they are not model-authored plan JSON. `eda/blocks/spice-runner.ts` is the separate Bun worker and the only layer importing the pinned `@tscircuit/ngspice-spice-engine@0.0.20`. It checks installed package metadata before reporting that engine identity.

The Node wrapper requires passing ERC/power plan checks, then binds recipes to actual parts, value citations, net membership, plan links, ground and declared source voltages. Actual resistor/capacitor strings are parsed into bounded numeric SI quantities. Changed instance parameters require rematerialization through existing ERC. Extra unmodeled loads/drivers at reset/divider/LED midpoint fail the profile. Only numeric fixed templates cross the worker boundary; user/model names, netlists, directives, filesystem paths and remote model URLs are not accepted as circuit text. Existing `runWorker` uses its explicit environment allowlist and process-group timeout (30 seconds default, 60 seconds maximum here).

Supported profiles and units:

| Recipe | Actual circuit binding | Measured output | Fixed model scope |
| --- | --- | --- | --- |
| `rc-reset` | Named R supply→midpoint, named C midpoint→GND | Linear-interpolated threshold-crossing time, **ms** | Ideal R/C, initial capacitor voltage zero; declared supply and threshold ratio |
| `divider` | Named upper/lower resistor, supply→midpoint→GND | Simulated midpoint **V** | Unloaded except declared high-impedance input pins |
| `resistor-current` | Named resistor between actual supply and GND | Native source-current samples, **mA** | Ideal resistor |
| `led-current` | Named series R; actual two-pin passive D anode→cathode to GND | Native source-current samples, **mA** | Recipe's fixed forward drop, explicitly not a diode/temperature/dynamic model |
| `charge-current` | Named R from actual declared charger PROG/ISET pin to GND | Native ideal-law mirrored current, **mA** (1 Ω output sense) | Datasheet coefficient **A·Ω** / actual R; explicitly not charger/battery/thermal/safety prediction |

`target` and `tolerance` are absolute values in the profile's measured unit, not percentages. Each result compares actual native samples to that interval. The RC calculation extracts a threshold crossing from native sampled waveforms; it does not substitute the analytical RC equation for simulation. A fixed-template current mirror implements the supplied ideal charger programming law inside SPICE. Its result cannot validate whether the cited law is correct; independent datasheet review still must do that.

At most 32 recipes run serially in one worker. Numeric bounds limit transient point count/time constants. Runtime input JSON is capped at 32 KiB and output at 16 MiB. Missing required component/reference/topology, unsupported recipe/model, malformed measurement, absent engine or worker failure yields a failing SPICE gate. No recipes yields an explicit passing limited-coverage warning, not a claim of analog verification. Every simulated plan also reports that only declared profiles were checked.

Artifacts live in `MOKI_BLOCK_SPICE_DIR` or `var/block-spice/run-*` (isolatable `artifactDir` for tests): input JSON, actual generated netlists and raw engine CircuitJSON results in `output.json`, and plan/block hashes/recipes/measurements/gate in `gate.json`. An input SHA-256 binds worker output to its request. Returned `spice-evidence` warning identifies the audit output path. Missing output/error does not create simulated measurements; input evidence remains on failure.

## Explicit normally-open reset switch model

`BlockPart.switch: 'normally-open'` authorizes an open-state reset contact only. The RC profile follows normalized actual plan connections, including cross-instance port links, to require one contact on the measured reset node and the other on a declared ground node. The switch must expose exactly two non-NC electrical pins, each passive or ground, have no supplied component `value` (including an empty value), and have a datasheet page citation. A matching reference prefix or ordinary passive pin alone never authorizes omission. Other unmodeled loads still fail; divider/LED profiles do not silently acquire this reset-specific model.

The generated netlist records a fixed comment stating how many explicitly declared reset switches are held OPEN. Only the validated integer count enters this comment; author-supplied identifiers never enter SPICE text. Full scoped identities appear in the audit profile and `spice-open-switch` warning. Closed, pressed and contact-bounce behavior remains outside this model. The accompanying ERC schema addition is present. Focused switch checks passed **2/2**, 0 failures/skips, 2101.67 ms total; actual native cross-instance RC portion 1721.49 ms. The RC crossing remained 13.862942 ms. `native-open-switch-result.json` preserves the actual waveform, fixed open-state netlist comment and audit identity `button.K1`. Negative cases reject missing switch declaration, conflicting value, active/extra electrical contacts, a floating return, and missing citation. A final guard-fixture refinement preserves a separate valid ground anchor while floating the passive return, so the SPICE topology check itself must reject that case; this guard is rerun without a native engine.
