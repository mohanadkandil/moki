# Maker edits — implementation boundary

The public API uses absolute `pcb_component.center` positions. The pinned tscircuit manual placement implementation uses the component's authored footprint origin, so a stored layout resolves the centre-to-origin offset in local coordinates and rotates that offset with the part. Source code stays immutable across edit jobs.

`src/board/edits.ts` owns strict input parsing, base-layout reconstruction, normalized physical poses, board/USB constraints, envelope collision checks and factual diffs. `server/board-api.ts` owns base-job recovery, queue admission, persistence and cache identity. `eda/apply-layout.ts` applies trusted `manualEdits.pcb_placements` through public component `setProps`, clearing conflicting explicit PCB coordinates and setting absolute `pcbRotation` (the installed manual placement schema does not carry rotation). `eda/render.ts` remains the routing/output stage and derives updated metadata from the resulting circuit. The existing mechanical handoff follows real pad positions and the board outline; it remains the case geometry interface.

A complete canonical layout is persisted per job, separate from the user's delta edits. Cache identity includes source plus canonical layout, ensuring board edits never reuse unedited circuit/GLB artifacts. A source-only child restores the stored source/layout; a design-backed child restores its saved validated graph so placement edits preserve firmware generation. Verified firmware reuse is keyed by actual generated source/configuration, not template identity or pin equality alone, so behavior changes also compile.

Before queue admission, unknown keys, nonfinite/missing dimensions, unknown/duplicate parts, unsafe source-base geometry, out-of-board modules, module-envelope overlaps, inaccessible USB and board mounting-hole conflicts produce a plain HTTP 400 with no job directory. Successful output echoes normalized input edits/base identity and a top-level editSummary. A post-render consistency assertion rejects a renderer that failed to apply the requested poses instead of falsely claiming an edit landed.

Scope: deterministic single-board catalog carrier edits. No wiring, manual routing, via, pour or schematic edits. Runtime failure shapes remain unchanged. Source/model uncertainty, DRC limits and unmeasured physical fit remain disclosed. Production is untouched. Source implementation and pure/API tests are complete; native acceptance is recorded in edit_core.md.
