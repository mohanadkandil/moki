# Immutable native clock preloads

Helper `eda/blocks/immutable-preloads.ts` is frozen at `afde60c008104bb6e9c6f87495567b725989f3c408b4df91f8132d2dc7fce7df`; focused tests at `94acdaf66b747948596e42ea41c0efcebae094437ab634671abebd419dfa90cc`.

This helper uses the official SRJ `traces` preload representation to retain fixed clock copper and ownership in native references. It does not change the native SDK, solver, paths, widths, layers, source ownership, or clearance settings. The fixture contains the exact current five CJ clock records from job `71e5d163-a9c4-47f1-b00b-55896bb5af8d` and its full remaining-phase callback input. The records include their actual source/subcircuit IDs and route direction, rather than reconstructing clock routes from obstacles. The existing 111 generic clock rectangles and eight associated physical pad obstacles remain present.

`prepareImmutablePreloads(input, actualFixedTraces)` returns a cloned input, a separate deeply frozen expectation, and an audit. It requires all five caller-proven clock traces with three distinct owner names and counts [1, 2, 2], rejects active owner aliases, duplicate trace IDs and unsupported fixed data, and appends literal records without projecting metadata. Any preexisting preload is also preserved and included in the immutable expectation.

`verifyImmutablePreloads(solver, output, expected)` requires both official public preload getters. Every updated record must match its exact original canonical full-record hash, with complete and unique coverage; the mutated getter must be empty. Unknown, omitted or changed preloads reject. Every returned expected preload is checked for exact full-record equality, including unrelated prior preloads. Returned clock IDs are removed only when their full records match exactly, because Core already contains those five traces. A replacement claim against any expected preload rejects. Other output copper and metadata remain untouched; unrelated existing preloads are never stripped. Both SRJ and trace-array output shapes are supported.

Canonical comparison uses the existing `nativeReplayInputSha256`, preserving array order and exact finite numbers while treating optional undefined object keys as JSON-absent. It does not round coordinates, normalize routes, merge aliases or tolerate changed geometry.

Measured: **8/8 focused pure tests pass**, with strict targeted TypeScript passing. Actual fixture and mutants cover route coordinates, direction, width, layer, via insertion, source/subcircuit ID, alias order, trace ID, unknown data, missing/duplicate records, replacement claims, stale expectation mutation, renumbered nets/traces/source/subcircuit IDs and root aliases on two/four layers, and optional undefined object keys. No solver step, routing, whole-board oracle, render, firmware compile or service change was performed. This is a fail-closed representation contract; fresh native and physical-copper gates remain mandatory for any actual board acceptance.

The caller owns clock-semantic selection via its existing clock profile. The helper hardcodes no net IDs, component references or part-order assumptions. Independent review identified and closed a returned-output immutability gap for optional unrelated prior preloads; regressions preserve their literal records and reject changed or replacement copies.
