# Public block testing contract and acceptance limits

5 November 2026. Implemented `src/blocks/test-block.ts`, `tests/blocks-test-block.test.ts` and the public root-index `testBlock` export. Coordinator separately added native `import-map.json` output and explicit nonsecret block-store directory keys to the existing worker environment allowlist. No native build, native SPICE invocation, firmware compilation, promotion or production change ran during this implementation.

`testBlock(draft: BlockDraft, options: { plan: BoardPlan; outputDir?: string; timeoutMs?: number }): Promise<BlockTestReceipt>` requires a **qualified real context**. The context must contain an instance resolving to precisely `contentHash(draft)`, either through an identical inline `plan.drafts` revision or an already saved/cached exact revision. The function never fabricates batteries, power sources, pullups, MCU bus pins or fake harness parts to make an isolated block pass. An I2C draft therefore needs its actual source, ground return, controller and pullups in the context. Context definitions and actual catalog receipts resolve through the existing block library.

For agent_core: construct the actual intended plan with the new unreviewed draft and all real links, pass local draft and complete-plan ERC/power checks, obtain the independent code-validated schematic review for that exact electrical identity, then call `testBlock(draft,{plan,...})`. Review is read through `checkSchematicReview`; authored status/flags never create approval. Missing current review stops before any SPICE/native execution. Requirements for the device remain the separate Verifier/device pipeline's responsibility. This operation does not save/promote a block or call `recordIndependentReview`.

After prerequisites, the function runs the current-hash SPICE gate, then bounded Bun `eda/blocks/build.ts --job <new isolated directory>` through existing `runWorker`. It reads the actual native receipt, CircuitJSON and import map. A DRC pass requires checked native DRC with no errors in the receipt **and** no CircuitJSON `_error` records, plus successful worker exit. The block-test gate separately inspects the targeted draft's actual native PCB pad shapes. Every mapped physical pad, including declared NCs, must have a valid copper shape corresponding through source-port and PCB-port identities plus the pinned importer's native pad hints. Omitted pads must be absent; unknown extra copper pads, degenerate/unsupported shapes, duplicate mappings and stale context/block/catalog/footprint identities fail. The import map must bind `inputHash` to current `schematicHash(plan,blocks)` and each part to the exact block content hash and catalog footprint hash.

MCU drafts always carry a compile gate. A real context `plan.app.source` is mandatory; compilation uses `src/board/chip-firmware-worker.ts` and its existing PlatformIO sandbox path, without changing compiler behavior. Missing application source, failed/missing compile evidence, skipped compilation or nonzero worker exit cannot pass. A non-MCU draft does not claim a firmware compile; the complete device pipeline still owns application acceptance.

Receipts retain exact draft content hash, timestamp, gate results, artifact paths and elapsed milliseconds. Missing prerequisites leave downstream required gates explicitly not run/failed. Failures return an honest receipt instead of fabricating native evidence. Each request creates a fresh `run-*` child under `outputDir` (default `var/block-tests`), preventing reuse/overwrite of stale outputs. Supplied roots are restricted to workspace or OS temporary storage and cannot contain traversal or symbolic-link ancestors. Fixed execution options do not allow worker injection. Artifacts include plan/draft, current SPICE gate, actual native/firmware logs and outputs, and `block-test.json` as available. Default total deadline is240 seconds, bounded1–600 seconds; it is shared across worker stages.

Measured validation: **5/5 pure tests pass**, no failures/skips, **820.90 ms** reported total. Real retained SHT40 and seed-context catalog data prove prerequisite failures occur before native execution, including missing/stale context, missing power/controller links, authored review flags, invalid catalog identity, mandatory MCU compile status and isolated/safe paths. Synthetic physical-shape unit fixtures exercise actual pad-presence/omission logic (including forbidden SHT40 central EP reappearance), port-map consistency and identity failures; they are explicitly **not** native rendered geometry or DRC acceptance.
